
## Overview

### 1. Inside a Document

- [ ] Is all content within the document covered by items with IDs?
- [ ] In other words, descriptive text without an ID should only serve to elaborate on or supplement one of the ID-tagged items; there must be no requirements or constraints that are unique to those descriptions.
### 2. Traceability Matrix
#### 2.1. Checking for omissions using a traceability matrix

- [ ] Are all items linked to an input item allocated from the high-level design?
- [ ] Are all input items followed by items in this document?

#### 2.2. Sufficiency Review

*手順:* LLMにレビューを依頼する前に、上位設計から割り当てられたアイテムそれぞれについて、この文書でフォローしている項目のリストを作成する
そののち、割り当てられた各アイテムについて、以下のチェックをLLMに依頼する

- [ ] 割り当てられたアイテムは、この文書でフォローしている（Traceしている）アイテムでカバーされているか
	- [ ] たとえば、四則演算機能を提供すること、という割り当てられた要求に対して、フォローしているアイテムが加減算しか言及していなければ、フォローは充分でない

#### A. 意味的包含関係のチェック (Semantic Coverage)

現在の「Sufficiency Review」をさらに深掘りする項目です。

- [ ] **暗黙的な要求（Implicit Requirements）の漏れ:** 上位設計にある概念が、下位設計では具体的な機能に落とし込まれているか？（例：「高いセキュリティ」という要求に対し、認証・認可・ログ出力などの具体的手段が設計に含まれているか）
- [ ] **境界条件・例外処理の欠落:** 要求事項には「正常系」の動作は書かれているが、それに関連する「異常系（エラーハンドリング）」の設計がトレーサビリティの連鎖の中で途切れていないか？

#### B. 一貫性と矛盾のチェック (Consistency & Conflict)

- [ ] **用語の一貫性:** 上位設計で使用されている重要な概念（エンティティ名や状態遷移など）が、下位設計でも同じ意味で使われているか？（名称が変わっていると、LLMは別のものと判断してトレーサビリティが切れる可能性があります）
- [ ] **論理的矛盾の検知:** 上位設計での制約条件（例：応答時間は1秒以内）に対し、下位設計の構成要素（例：複雑な多段プロセス）がその制約を物理的に満たせない構造になっていないか？

#### C. 粒度の適切性 (Granularity Check)

- [ ] **抽象度のミスマッチ:** 上位設計の「ビジネスルール」が、下位設計の「データ構造」に直接紐付いていないか？（間に「処理ロジック」や「インターフェース」などの中間層が必要ではないか）

#### D. 検証可能性 (Verifiability)

- [ ] **テスト可能性の確保:** トレーサビリティによって結び付けられた設計項目は、具体的なテストケースに変換可能なほど具体化されているか？（「使いやすいUIにする」といった抽象的な記述がそのまま設計として残っていないか）

---
 **【LLMへの指示構成例】**

**1. 目的:** 上位設計と本ドキュメントの間のトレーサビリティを、形式面および意味面から検証する。

**2. 検証対象:**

- 入力A: [上位設計の要求リスト]
- 入力B: [本ドキュメントの内容]

**3. チェック項目:**

- **[形式的チェック]** 全ての要求に、対応するIDが割り当てられているか？
- **[網羅性チェック]** 要求に含まれる全ての要素（正常系・異常系・制約条件）が設計でカバーされているか？
- **[意味的充足度チェック]** 設計の内容は、要求の意図を十分に満たす具体性を備えているか？（例：計算機能の要求に対し、演算子が不足していないか等）
- **[一貫性チェック]** 用語や論理構造に矛盾はないか？

**4. 出力形式:**  
| 要求ID | 状態 (OK/Partial/NG) | 不足している要素・理由 | 推奨される対策 |  
| :--- | :--- | :--- | :--- |
